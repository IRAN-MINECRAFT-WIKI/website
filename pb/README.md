# PocketBase — MineBed Backend

PocketBase is the only backend the MineBed website depends on at request time. Everything else is statically generated by Astro and deployed to GitHub Pages.

This directory holds the **schema export** and **hooks** that together define the backend. The running PocketBase server lives elsewhere (locally during development, on Fly.io in production).

## Collections

| Name              | Purpose                                                                                                       | Public create? | Public read? |
| ----------------- | ------------------------------------------------------------------------------------------------------------ | -------------- | ------------ |
| `seeds_queue`     | User-submitted seeds awaiting admin review (rate-limited 5/IP/day)                                           | ✅ anonymous    | ❌            |
| `seeds_published` | Approved seeds copied here automatically on approve; read by the daily GitHub Action to build the static JSON | ❌ admin only   | ❌ (read via Action with admin token) |
| `online_users`    | Live heartbeat table — front-end posts every 30s                                                              | ✅ anonymous    | ❌            |
| `visits`          | Per-page visit log (fire-and-forget POST from BaseLayout)                                                     | ✅ anonymous    | ❌            |

Full schema in [`pb_schema.json`](./pb_schema.json). Hooks (IP rate-limit + auto-copy on approve + CORS + cron) in [`pb_hooks/main.pb.js`](../pb_hooks/main.pb.js).

## Local development

### 1. Download PocketBase

PocketBase ships as a single self-contained binary. Grab the latest release for your OS:

```bash
# Linux (use this for Fly.io — same arch)
curl -L https://github.com/pocketbase/pocketbase/releases/latest/download/pocketbase-linux-amd64 -o pocketbase
chmod +x pocketbase

# macOS (Apple Silicon)
curl -L https://github.com/pocketbase/pocketbase/releases/latest/download/pocketbase-darwin-arm64 -o pocketbase
chmod +x pocketbase

# Windows
# Download pocketbase-windows-amd64.exe from the releases page
```

### 2. First run — create the admin user

```bash
./pocketbase serve --dir=./pb_data
```

Open `http://127.0.0.1:8090/_/` and follow the wizard to set up the admin email + password.

### 3. Import the schema

From the PocketBase admin UI:

1. Visit `http://127.0.0.1:8090/_/` and log in.
2. Click **Collections** → **Import collections**.
3. Choose **JSON** as the format.
4. Paste the contents of `pb/pb_schema.json` (or upload the file).
5. Click **Review + import**. PocketBase will create all 4 collections with their fields + indexes.

Alternatively, with the CLI:

```bash
./pocketbase migrate collections --dir=./pb_data pb/pb_schema.json
```

### 4. Restart with hooks loaded

PocketBase auto-loads every `*.pb.js` file inside `pb_hooks/` (relative to the working directory). Make sure you launch PocketBase from the repo root so it finds `pb_hooks/main.pb.js`:

```bash
cd /home/z/work/imc-website   # repo root — pb_hooks/ lives here
./pocketbase serve --dir=./pb_data --http=127.0.0.1:8090
```

If you see a console message like `[hooks] loaded: main.pb.js`, the hooks are live. The cron job `prune-online-users` should fire every 10 minutes; you can also trigger it manually from the admin UI → **Cron** tab.

### 5. Create the admin API token

The admin panel + the daily GitHub Action both authenticate with a PocketBase admin token (not user accounts — MineBed has no public user accounts).

1. Admin UI → **Settings** → **Admin users** → **Create**.
2. Note the email (e.g. `admin@minebed.local`).
3. To get an admin API token for the GitHub Action: POST to `/api/admins/auth-with-password` with `{"identity":"admin@minebed.local","password":"..."}`. The `token` field in the response is your `PB_ADMIN_TOKEN`.

```bash
curl -X POST http://127.0.0.1:8090/api/admins/auth-with-password \
  -H 'Content-Type: application/json' \
  -d '{"identity":"admin@minebed.local","password":"YOUR_PASSWORD"}'
# → {"token":"eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...","admin":{...}}
```

Use that token in two places:

- Front-end admin panel: pasted into the password box of `/admin-minebed-control`. Stored in `sessionStorage` (not localStorage) so it vanishes when the tab closes.
- GitHub Action: stored as the repo secret `PB_ADMIN_TOKEN`.

## Fly.io deployment (production)

The PocketBase server runs on Fly.io so it can serve CORS-preflight + persistence for the GitHub Pages site.

### 1. Install flyctl + login

```bash
curl -L https://fly.io/install.sh | sh
flyctl auth login
```

### 2. Launch the app

From the repo root:

```bash
flyctl launch --no-deploy
```

When prompted for the Dockerfile / buildpack, choose **Dockerfile** (we provide one). Fly will generate a `fly.toml` — edit it to:

```toml
# fly.toml
app = "minebed-pb"
primary_region = "arn"            # Stockholm — closest to Iran with low RTT

[build]
  dockerfile = "Dockerfile"

[http_service]
  internal_port = 8090
  force_https = true
  auto_stop_machines = false       # keep alive so the cron + heartbeat endpoints work
  min_machines_running = 1

[[http_service.checks]]
  interval = "30s"
  timeout = "5s"
  grace_period = "10s"
  method = "GET"
  path = "/api/health"
```

### 3. Create the Dockerfile

PocketBase's official Dockerfile pattern:

```dockerfile
FROM debian:bookworm-slim
WORKDIR /pb
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates wget unzip && \
    rm -rf /var/lib/apt/lists/*
RUN wget -q https://github.com/pocketbase/pocketbase/releases/latest/download/pocketbase-linux-amd64.zip && \
    unzip pocketbase-linux-amd64.zip && rm pocketbase-linux-amd64.zip && \
    chmod +x pocketbase
COPY pb_hooks/ ./pb_hooks/
EXPOSE 8090
CMD ["/pb/pocketbase", "serve", "--http=0.0.0.0:8090", "--dir=/pb/pb_data", "--hooksDir=/pb/pb_hooks"]
```

### 4. First deploy + create admin

```bash
flyctl deploy --vm-size=shared-cpu-1x-x512
flyctl apps open                  # opens https://minebed-pb.fly.dev/_/
# Set up the admin user via the web wizard.
```

### 5. Persistent volume

The `/pb/pb_data` directory holds SQLite. Mount a 1GB volume so data survives redeploys:

```bash
flyctl volumes create minebed_pb_data --region arn --size 1
```

Add to `fly.toml`:

```toml
[mounts]
  source = "minebed_pb_data"
  destination = "/pb/pb_data"
```

Redeploy: `flyctl deploy`.

### 6. Point the front-end at the production server

Set the GitHub repo secrets:

| Secret              | Value                                       |
| ------------------- | ------------------------------------------- |
| `PB_URL`            | `https://minebed-pb.fly.dev`                |
| `PB_ADMIN_TOKEN`    | `eyJhbGc...` (from the admin login POST above) |

These are read by `.github/workflows/publish-seeds.yml` and `scripts/fetch-approved-seeds.mjs`. The front-end admin panel reads the URL from a constant in `admin-minebed-control.astro` (currently defaults to `http://127.0.0.1:8090` for local dev — change it to your production URL before deploying).

## Environment variables

| Var               | Used by                            | Example                       |
| ----------------- | --------------------------------- | ----------------------------- |
| `PB_URL`          | GitHub Action + fetch script       | `https://minebed-pb.fly.dev`  |
| `PB_ADMIN_TOKEN`  | GitHub Action + fetch script       | `eyJhbGciOiJIUzI1NiIs...`     |
| `PB_URL` (front-end) | Admin panel (hard-coded constant in `admin-minebed-control.astro`) | same as above |

The front-end admin panel stores the admin token in `sessionStorage` under the key `adminToken`. This is **intentional** — `sessionStorage` is per-tab and disappears when the tab closes, so a forgotten logged-in admin session doesn't outlive the day.

## Troubleshooting

- **CORS errors in the browser console**: The hook only reflects the origin `https://iran-minecraft-wiki.github.io`. Local dev at `http://localhost:4321` will be rejected. Either (a) add your dev origin to the `ALLOWED_ORIGIN` constant in `pb_hooks/main.pb.js`, or (b) run the front-end build against the production PB server (point `PB_URL` at `minebed-pb.fly.dev`).
- **429 from `/api/collections/seeds_queue/records`**: IP rate-limit hit (5 / IPv4 / UTC-day). Wait until midnight UTC, or `DELETE FROM seeds_queue WHERE ip_address = '...'` from the admin UI to free the budget for testing.
- **Approve doesn't copy to `seeds_published`**: Check the PocketBase server logs for the line `Approve→publish copy failed (non-fatal): ...`. The hook's error path is non-blocking so the approve itself succeeds; the copy can fail if the SQL has a typo or the published table doesn't exist yet (re-import the schema).
- **The admin panel shows "Backend not available"**: The admin panel in `admin-minebed-control.astro` is designed to gracefully degrade — if PocketBase is down or unreachable from the browser, it shows simulated data so the page never breaks. Real data shows up the moment the backend becomes reachable. Check that `PB_URL` in the page's `<script>` matches your deployment.

## Why PocketBase (and not Supabase / Firebase / etc.)

- Single binary, single SQLite file → trivial backups (`flyctl sftp pull /pb/pb_data/data.db`).
- No vendor lock-in: data is portable SQLite, hooks are plain JS.
- Free tier on Fly.io is enough for the MineBed traffic (a few hundred req/day).
- Self-hosted → no data leaves our infra. Privacy note for Iranian users: no Google/Firebase analytics, no cookie banners, no third-party trackers.
